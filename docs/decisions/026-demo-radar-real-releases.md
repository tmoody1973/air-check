# 026: The judges' demo radar shows real, already-released releases with Bandcamp's player

**Decision.** The demo workspace's Release radar lists about ten real releases from the station's radar that are already out and already have a Bandcamp player, with their cover art and Bandcamp's own player, alongside the bracketed samples.

**Why this came up.** On Oct 30 Tarik compared the demo with his own radar. The demo showed only bracketed placeholders ("[Artist] – [Release title]") and no players, so judges could not see or hear what the radar does, even though it is one of the features he uses most.

**Options.**
1. Real, already-released releases with Bandcamp's player (chosen). The demo looks and plays like the real radar. Costs a change to how the demo applies the Sample Honesty Rule, and a small chance a label minds its release appearing in a public demo.
2. Keep bracketed placeholders only. No risk, but the radar looks empty to judges.
3. Invented releases. Rejected: the Sample Honesty Rule never invents releases.

**What we chose and why.** Option 1, Tarik's call. Only public facts travel (artist, title, label, type, genre, release date, Bandcamp page, player id, cover); never senders, emails, links, notes, reasons, or anything embargoed or unreleased. Rows keep the demo's Sample tag. The demo still cannot publish (Hard Rule 9), and none of this is Tarik's Bandcamp collection (Hard Rule 13). Playback is Bandcamp's own embedded player, loaded only when a visitor presses Play.

**What we gave up.** The demo is no longer purely bracketed samples, and the list is a snapshot: it does not update as the real radar does. A label could ask to be removed; removing a row is a one-line change.

**How we'll know if this was right.** Judges press Play on the demo radar (the Trust page logs nothing from the browser, so this is anecdotal: feedback, or no complaints from labels by Dec 15).
