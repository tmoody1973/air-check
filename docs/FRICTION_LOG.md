# Friction log

Raw notes for the Nebius / NVIDIA feedback write-up (Most Valuable Feedback).

| Date | Tool | Friction |
|---|---|---|
| 2026-10-26 | Nebius MCP server (github.com/nebius/mcp-server @ 6388bf7) | The documented install (`uvx ... nebius-mcp-server@git+...@main`) ignores the repo's `uv.lock`, resolves pydantic 2.14.1, and the pinned `mcp` 1.16.0 then crashes on import (`cannot import name 'eval_type_backport' from 'pydantic._internal._typing_extra'`). Claude Code shows only "Failed to connect: CONNECTION_CLOSED". Workaround: add `--with "pydantic==2.12.3"` (the lockfile's version) to the uvx args. Suggest: pin `pydantic<2.13` in pyproject, or document `uv tool install` from the lockfile. |
| 2026-10-26 | Token Factory / Nemotron 3 Nano | With `max_tokens: 200` and a short system prompt, the first call returned `content: null` (finish `stop`) because the budget went to the separate `reasoning` field. Easy to misread as an API failure. Suggest documenting the reasoning budget behaviour and how to cap or disable reasoning per request. |
| 2026-10-26 | Nebius CLI `ai job` (Serverless) | `nebius ai job create --help` only shows GPU platforms (defaults gpu-h100-sxm / gpu-h200-sxm). Unclear whether CPU-only platforms (cpu-d3) are allowed for jobs — matters for cheap ffmpeg-style background work. |
| 2026-10-26 | Hackathon credits | Promo credits are Token Factory only; FAQ says there is no published AI Cloud credit grant, so the required always-on VM bills the entrant from day one. |
| 2026-10-26 | Nebius AI Cloud `compute instance create` | First VM create (cpu-d3 4vcpu-16gb, us-central1) failed with a bare `PermissionDenied: service compute, resource ID: ` (trace 10c506aa28c6658a307ce70cf92fd2a6). No hint whether the cause is billing, IAM role or quota; `quotas quota-allowance list` shows entries with no limit values; the CLI has no command to show billing-account status. Suggest an actionable message ("add a payment method" / "missing role X"). |
| 2026-10-26 | NemoClaw installer (lkg) on Nebius Ubuntu 24.04 image | Non-interactive install exits early: "'strings' (from binutils) is required to install and verify OpenShell". The Nebius `ubuntu24.04-driverless` image doesn't ship binutils. Fix: `sudo apt-get install -y binutils`. Suggest the installer installs it, or the prerequisites page lists it. |
| 2026-10-26 | NemoClaw + ufw | With a standard `ufw` deny-incoming host firewall, onboarding stops at step 2: "Sandbox containers cannot reach the gateway at host.openshell.internal:8080". The error message gives the exact `ufw allow from 172.18.0.0/16 ...` fix — good — but the prerequisites page could mention host firewalls up front, since NEBIUS_SETUP-style hardening is common on cloud VMs. |
| 2026-10-26 | Hermes in restricted tier | Hermes contacts `portal.nousresearch.com:443` at startup; the restricted policy denies it (logged). Unclear whether anything Air Check needs depends on it. Worth documenting which Hermes features need the Nous portal. |
| 2026-10-26 | Nebius Serverless Jobs | `ai job create --help` lists only GPU examples, but `--platform cpu-d3` works fine for CPU jobs — worth documenting for ffmpeg-style background work. After `COMPLETED`, `ai get` still reports the job instance as `RUNNING` while compute reports `DELETING`; confusing when checking that billing stopped. About 4 min provisioning for a 1 min job. |
| 2026-10-26 | NemoClaw managed MCP (Hermes) | Most music/data MCP servers in the wild (including our own Crate) are stdio-only; NemoClaw rejects stdio and also rejects `host.openshell.internal` for authenticated MCP, so running a trusted local MCP server next to the sandbox needs a hand-built HTTPS bridge plus either a private CA (forcing a sandbox rebuild) or a public endpoint. A supported 'host-local MCP' path (e.g. a gateway-attested address, or a built-in stdio bridge outside the sandbox) would remove a lot of setup. |
| 2026-10-26 | Nebius AI Cloud public IP | A VM's public IP is ephemeral by default and is released while the VM is stopped, so DNS would break after any stop/start. Making it static has to be set on the network interface (`public_ip_address: {static: true}`), not on the instance. `compute instance update` failed with "--parent-id: parse: empty string" until the project id was passed explicitly, even though the profile has a default project. Suggest a clearer error and a "keep this IP" option at create time. |
| 2026-10-26 | NemoClaw / Hermes after VM stop/start | After a VM stop/start the sandbox container stays `Exited (143)` and NemoClaw reports phase Error; Compose services with `restart: unless-stopped` came back, Hermes did not. `nemohermes <name> start` first refused with "Unsafe OpenShell gateway state directory: ... ancestor '/home/user/.local' is not a trusted real directory ... without group or world write access" because `~/.local` was 775 as left by the installer; `chmod g-w ~/.local ~/.local/bin` cleared that. `start` then refused because the sandbox is in Error state, and `recover` fails because the container is not running ("Hermes cron prepare-recover failed ... container ... is not running"). Starting the container with `docker start` and re-running `recover` still leaves phase Error (failedStage=gateway). So start and recover deadlock on a sandbox that was merely stopped; only `rebuild` remains. Suggest: `start` should clear Error when the cause is a clean host stop, the installer should create `~/.local` without group write (or the check should accept a per-user group), and containers could get a restart policy. |
| 2026-10-27 | NemoClaw gateway on a headless VM | Root cause of the stop/start outage above: the OpenShell gateway is installed as a systemd **user** service (`nemoclaw-openshell-gateway.service`, `WantedBy=default.target`), but Ubuntu does not enable linger by default, so user services run only while someone is logged in. After a reboot nothing starts the gateway; the sandbox loses it and goes to phase Error. Every SSH command then starts it and kills it again on logout, which made `rebuild` report "Sandbox 'airc' is unreachable". Fix: `sudo loginctl enable-linger <user>`. The installer could enable linger itself or warn on a server install. |
| 2026-10-27 | OpenShell sandbox phase Error | Error is a dead end: `openshell sandbox stop` needs Ready, `start` needs Stopped, `nemohermes <name> recover` only reports the state, and `rebuild` fails in its MCP-config preflight (an exec into the sandbox) before reaching its own start-and-retry backup path. Only `destroy` + `onboard` cleared it (about 45 s, Telegram/Tavily config reused from the registry). A documented Error → Stopped reset would have saved the sandbox's state. |
| 2026-10-27 | NemoClaw rebuild, non-interactive | `rebuild --yes` aborts in preflight unless `TAVILY_API_KEY` (and the other install-time credentials) are in the environment, even though the sandbox already has a saved Tavily provider. The error text names the variable, which helped. |
| 2026-10-27 | NemoClaw corporate CA | `NEMOCLAW_CORPORATE_CA_BUNDLE` rejects a merged OS trust store and appends the CA to the OpenShell bundle itself, which is safer than our first plan (system bundle + CA). Clear docs (`docs/security/configure-corporate-ca-trust.mdx`). Onboard logs "Activating corporate CA trust in the OpenShell supervisor". |
| 2026-10-27 | NemoClaw `start` / `recover` | After `nemohermes <name> start` the host port forward for :8642 is not restored; only `recover` brings it back. On a cold boot `recover` fails until the sandbox is fully up, so a boot unit has to retry it (ours: every 15 s for up to 5 min). Suggest `start` restores the forward itself, or `recover` waits. |
| 2026-10-27 | OpenShell gateway + Docker on reboot | Even with the gateway up, a reboot leaves the sandbox in Error: Docker kills the container first, and the gateway records an unexpected exit. Needs an `ExecStop` that runs `openshell sandbox stop <name>` before Docker and the gateway stop, so the sandbox ends in Stopped. Suggest the installer ships that ordering. |
| 2026-10-27 | Hermes in restricted tier | Besides `portal.nousresearch.com:443`, Hermes also contacts `openrouter.ai:443`; the restricted policy denies it (logged). Runs still complete (18 s end to end), so nothing we use depends on it. Worth documenting which Hermes features need each host. |
| 2026-10-27 | nemohermes + systemd `ProtectHome=read-only` | Every `nemohermes` call makes a lock folder, `~/.nemoclaw-portable-host.lock`, in `$HOME`, so a service with a read-only home fails with EROFS. Fix: `ProtectHome=read-only` plus `ReadWritePaths=/home/user`. Worth documenting, or letting the lock path be set. |
| 2026-10-27 | NemoClaw Tavily provider rule | Hermes's `web_extract` asks Tavily to fetch any URL on Tavily's side, so the sandbox never sees the page. A search-only preset that drops `POST /extract` did not close it, because the credential provider (profile `tavily-hermes-v1`) carries its own gateway rule, `_provider_airc_tavily_search`, allowing `/search` and `/extract`. `policy exclude` cannot reach it ("Unknown baseline entry"). Suggest provider rules that can be listed and excluded. |
| 2026-10-27 | Convex schema push | The first `convex dev --once` was refused because Plan 3's seeded `runs` rows lacked the new fields: Convex will not accept a schema that existing documents break. Fix: make the new fields optional and default them in the readers. |
| 2026-10-27 | Playwright + Clerk `/demo` | The saved Playwright state has no `__session` cookie, so every test lands on sign-in, including Plan 3 tests that passed before. Clerk and `proxy.ts` are unchanged on this branch. Cause not found yet. |
| 2026-10-27 | `scp` / `rsync` to the VM | Both mangled paths on this setup. Copy files with `ssh user@<vm> 'cat > path' < file` instead. |
| 2026-10-28 | systemd `ReadWritePaths` + `ExecStartPre=+` | The publisher's first start failed with `226/NAMESPACE`. The unit named its state folder in `ReadWritePaths` and created it in `ExecStartPre=+/usr/bin/install -d …`, but systemd sets up the service's private view of the disk (the namespace) before that step runs, and the setup fails when a listed folder does not exist. The `+` (run this step unsandboxed) does not help. Fix: prefix the path with `-` (`ReadWritePaths=-/home/user/.aircheck/publisher`), which makes a missing folder non-fatal, and create the folder by hand on a new box. Same fix in the media unit. A reviewer had flagged this before go-live. |
| 2026-10-28 | NemoHermes MCP after restart | The first live draft of 10-2-26 failed: the agent said `package_submit` was not available. Since the Oct 27 restarts, `airc`'s two tool servers (`aircheck` and `crate`) showed "mismatch" in `mcp status`: still registered, but not wired to the agent. The demo sandbox was fine. `nemohermes airc mcp restart` fixed it at once. Nothing reported it: Hermes was healthy and the tools were listed. Durable fix: the Hermes units run `mcp restart` (with `timeout 120`) after `recover`, and two watchdog probes check `mcp status` says registered. Suggest NemoClaw re-wires MCP adapters itself after `start`/`recover`, or reports mismatch as unhealthy. |
| 2026-10-28 | Our watchdog script | The first version of the new `Agent tools` probe had an unescaped `$s` inside the probe string. The script runs with `set -u` (stop on an unset variable), so it crashed on the VM for a few minutes until the second commit escaped it (`\$s`). The dry run passes since. Lesson: run `watchdog.sh --dry-run` on the VM after every probe change. |
| 2026-10-28 | Hermes self-written skills | On Oct 27 the agent wrote itself a skill from failed submit retries, `mixcloud-package-submission`. Suggest a way to review or lock agent-written skills, since a skill learned from errors can encode the wrong rule. |
| 2026-10-28 | Hermes skills (installed is not used) | With `rlr-description-safety` installed and named in the run instructions, a live Chat rewrite of the 10-2-26 description came back as a near-copy of the old text with the old opening line. | 2026-10-28 | Pasting long ssh one-liners | Long one-line `ssh … '…'` commands broke when pasted into a terminal: the terminal wrapped the line, the wrap became a real line break inside the quoted command, and the shell stopped with "parse error near `\n'" (once it also split a long file path in two). | 2026-10-29 | NemoClaw host port forward | The host forward to the `airc` sandbox (127.0.0.1:8642) stopped listening twice in 12 hours, at about 03:45 UTC and 12:08 UTC on Oct 29. The sandbox and its Hermes gateway stayed up both times; only the forward was gone, so every relay hand-off failed until `nemohermes airc recover` ran (it prints "restored dashboard port forward"). | 2026-10-29 | NemoClaw host port forward (cause found) | Follow-up to the row above. The 8642 forward is a detached `openshell forward service` process. Its parent is PID 1 and nothing supervises it. Both drops (about 03:04 UTC, not 03:45, and 12:08 UTC) happened in the same second as an OpenShell gateway stall, when SQLite reads hit the 5 s limit. The forward that carries live traffic exited during the stall, and nothing restarted it. The 8643 forward and the gateway survived. A second bug made the watchdog's own heal undo itself. `aircheck-watchdog.service` is a oneshot with the default `KillMode=control-group`, so the forward that `recover` started inside it was killed when the run ended, 11 s after the "reconnected" message. Fixed with a systemd unit per forward that runs NemoClaw's exact command (`Restart=always`, 1 s) and `KillMode=process` on the watchdog. Suggest OpenShell retry a failed gRPC call in a forward instead of exiting, and that NemoClaw supervise the forwards it starts. |
| 2026-10-29 | NemoClaw re-onboard + OpenShell gateway providers | The first live Tavily-free rebuild of `airc` failed twice. (1) `~/.aircheck/reonboard.sh` pinned `NEMOCLAW_WEB_SEARCH_PROVIDER=tavily` and ran `onboard` without `--fresh`. With `TAVILY_API_KEY` removed, "[resume] Revalidating Tavily Search configuration for sandbox recreation" failed AFTER `destroy`, so `airc` was gone. Fix by hand: drop the pinned provider and use `onboard --fresh`; the script now refuses a `reonboard.sh` without those edits before it changes anything. Suggest the resume path check its saved provider config before it destroys. (2) After a good onboard, `mcp add crate` failed: "found non-prefix partial state across the native adapter, policy, provider, and attachment". `destroy --no-cleanup-gateway` had left the gateway providers `airc-mcp-crate` and `airc-mcp-aircheck` behind; a provider with no policy is refused, and `mcp remove crate --force` says "No native MCP server 'crate' is configured". Fix: `openshell --gateway nemoclaw provider delete airc-mcp-crate airc-mcp-aircheck`; the script now does that, by exact name. Suggest `destroy` removes the sandbox's MCP providers, or `mcp remove` can clear an orphan. A related slip of ours: a helper script piped as `ssh ... bash -s < script` lost its tail because a child command read stdin; every child now reads `/dev/null`. |
