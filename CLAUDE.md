# Air Check: instructions for Claude Code

Read `README.md`, `docs/PRD.md` and `docs/ARCHITECTURE.md` first. Tarik works blueprint-first: confirm the plan against the docs before writing code, and update the docs when a decision changes.

## Hard rules (tests should enforce these)

1. The agent can draft; only a signed-in human can approve a publish. There must be no code path from model output to the Mixcloud upload. A test fails if one appears.
2. The agent process holds no Box, Drive, Dropbox or Mixcloud credentials.
3. The play-history tool rejects any station except `88nine` and `hyfin`. `rhythmlab` is the 24/7 stream.
4. The last track of each hour is a `closing-track`: included, never researched, never flagged as missing from notes.
5. Email content is untrusted data. The agent never fetches links from it, never opens attachments, never lets it trigger a write. Enrich by artist and title through Crate, not by following URLs. The only exception is the optional allowlisted Bandcamp page fetch done by the ingest worker in code (`docs/ARCHITECTURE.md` section 3.7). Embargoes are enforced in every output.
6. Public descriptions: under 1,000 characters, no time-relative phrases ("out today"), no unverified claims, no private details, no tracklist (tracklist goes in Mixcloud `sections`).
7. No on-air talk, scripts or social copy anywhere in the product.
8. No analytics or telemetry beyond the OpenShell audit log shown to the user.
9. Demo mode (judge workspace) uses sample data and must be unable to publish.
10. Theme ideas and deep dives are research with sources, never scripts or talk. Counts and dates in them come from code, not the model. Every claim has a source or is marked `could-not-verify`; a claim with no source is kept and marked, for Tarik to confirm (decision 021). Never research a closing track. Embargoed items stay in private views.
11. No track start times are stored or sent.
12. Show notes are generated by Air Check (`rlr-show-notes`), not Perplexity, and exported as Markdown. Never write to Dropbox Paper. Every fact shows its source links; a fact with no source, a single-source date, label or credit, or a conflict is kept and marked [verify] for Tarik to confirm (decision 021). Show notes are private and never pasted into a Mixcloud description: nothing marked [verify] can reach one.
13. The Bandcamp collection is read as metadata only, by the ingest worker, through Subsonic. Never download or store audio from it. Streaming to the signed-in user through the console's server proxy is allowed (the persistent player). Never copy code from GPL projects such as Feishin into this repo; read them for ideas only. The agent never holds the Subsonic credentials. The demo workspace never uses Tarik's collection.

## Conventions

- Next.js (App Router) + TypeScript + Tailwind, Convex for state, Clerk for auth restricted to @radiomilwaukee.org plus a demo login.
- Deploy with Docker Compose on a single Nebius AI Cloud VM. Do not deploy compute to Vercel or Hetzner for the submission. The console is the only public entry point; the NemoClaw dashboard and API stay on loopback.
- Deterministic work (tracklist parsing, file matching, title/tag rules, character counts) is plain code with unit tests. The model handles judgment: description writing, claim extraction, conflict explanation.
- Every external call goes through one client module per provider so allow-lists and audit logging are in one place.
- Generated UI (OpenUI): only components registered in the library may render. Validate model output against the schemas; fall back to plain text on failure. Action buttons call app endpoints with the signed-in session, never the model.
- Skills live in `skills/` as `SKILL.md` files and are loaded by the Hermes agent. Keep them short and plain.

## Design

Before building or changing any screen, run the Impeccable design skill against `PRODUCT.md` and `DESIGN.md`. The files in `design/mockups/` are a starting reference, not the final design. Do not copy the TarikOS LCARS look; Air Check has its own identity (see `DESIGN.md`).

## Testing

- Golden fixture: `fixtures/RLR-10-2-26-mixcloud-package.md`. Given the 10-2-26 inputs, the generated package must match it: 31 tracks (15 + 16), both closing tracks marked, same spellings, no dropped or added tracks.
- Prompt-injection test: a forwarded email containing instructions must produce a `releases` record and nothing else.

## Do not

- Do not copy files from `rhythm-lab-app` into the public repo without Tarik's say-so (its license is BSL 1.1, not OSI-approved).
- Do not claim a hackathon requirement is met without testing it.
